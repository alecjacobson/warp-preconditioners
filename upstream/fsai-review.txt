FSAI review and upstream preparation
===================================

Scope
-----
The candidate branch contains scalar adaptive FSAI, its private construction,
packing, refit and application kernels, NumPy-only unittest coverage, API export,
preconditioner factory integration, test registration and API documentation.
It does not include benchmarks, assets, geometry/problem setup, BlockJacobi,
experimental block FSAI, SparseOperator or the standalone quality estimator.

Findings fixed
--------------
1. A zero kap_tolerance did not actually disable early stopping. On a 32-row
   tridiagonal SPD matrix (diagonal 3, off-diagonal -1), supports stopped at 20
   entries when energy improvement rounded to zero. The new condition only
   checks improvement for a strictly positive tolerance. CPU and CUDA reproduce
   the original failure; a regression requires all 32 entries and checks the
   factor against independent principal-submatrix solves.

2. reuse_pattern=True rejected an empty matrix because Warp disallows columns[:0].
   The topology snapshot now handles zero active entries explicitly. Regression
   coverage constructs, applies and updates empty float32/float64 operators on
   both CPU and CUDA.

Additional hardening
--------------------
- Validate finite factor entries and a positive diagonal before publishing even
  when storage precision is unchanged; previously only compression was checked.
  This adds no extra kernel or host synchronization to the construction path.
- Use Warp's existing BSR lookup in the upstream port instead of duplicating
  binary search routines.
- Give generated construction kernels unique modules, avoiding accumulation of
  all width/step/dtype specializations in one module.
- Skip the first sparse product when alpha is zero, so ignored x values are not
  consumed. Preserve the existing no-read behavior for beta=0.
- Document canonical BSR input, both-triangle storage, local pivot truncation,
  refit rollback, capture limits, scratch ownership and non-differentiability.

Validation coverage
-------------------
Independent NumPy solves verify local factors, full-pattern inverse identities
and adaptive support selection. Native tests also cover float32/float64, scalar,
1x1 matrix and 3x3 block storage, padded input, stored zeros becoming nonzero,
unused capacity, narrow frontiers, mixed storage, every cooperative lane count,
all alias combinations, zero alpha/beta, CG/CR true residuals, failed refits,
unchanged factor buffers and CUDA graph replay after updates.

Tests use NumPy only; no SciPy or external numerical backend is used by FSAI.
Numerical matrix construction, factorization, packing, transpose, refitting and
application all run through Warp on the matrix device.

Add an adaptive factorized sparse approximate inverse preconditioner for SPD
BSR matrices, with CPU/CUDA construction and application, mixed-precision

The implementation assumes SPD input; it does not perform global symmetry or
positive-definiteness validation. Each instance owns scratch, so use separate

rebuild after substantial numerical changes. Setup/refits synchronize; warmed
application is CUDA graph-capturable. G and GT are inspection-only arrays.
