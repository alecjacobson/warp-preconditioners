## What problem are you trying to solve?

Jacobi preconditioning converges slowly on the SPD biharmonic and elasticity systems in [warp-preconditioners](https://github.com/alecjacobson/warp-preconditioners). These workloads need a stronger preconditioner built and applied in Warp, including repeated solves with fixed sparsity and changing numerical entries.

**This is a handoff PR on `alecjacobson/warp`. Alec will repost it to internal NVIDIA Warp from another machine.**

## What does this change?

Add `warp.optim.linear.FSAI` and `preconditioner(A, "fsai")`. Adaptive, diagonally equilibrated row construction produces a lower-triangular factor `G`; application uses `G.T @ G`. Square BSR blocks are scalarized on device. No multigrid, external factorization, SciPy numerical backend, benchmarks, assets, or experimental block preconditioners are included.

Retain batched support growth, optional float32 factor storage with matrix-precision accumulation, cooperative CUDA application, and transactional fixed-pattern refits. The seven-file diff includes the implementation, tests, and API/documentation/test registration.

```python
from warp.optim.linear import FSAI, cg

M = FSAI(A, max_row_size=16, reuse_pattern=True)
cg(A, b, x, M=M)
# Modify A.values while preserving compact BSR topology.
M.update()
cg(A, b, x, M=M)
```

The review fixed two bugs in the downstream implementation: `kap_tolerance=0` could still stop growth when improvement rounded to zero, and reusable empty matrices failed on a zero-length slice. Construction now also checks factor validity before publication without adding a validation kernel or synchronization.

Input must be canonical SPD BSR with both triangles stored; global symmetry/SPD validation is not performed. Setup/refits synchronize. Warmed application supports CUDA graph capture. Each instance owns scratch and must not be applied concurrently on separate streams. Refits preserve supports and reject invalid updates without changing either factor. No automatic differentiation is provided.
