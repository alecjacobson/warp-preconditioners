## What problem are you trying to solve?

Jacobi preconditioning converges slowly on the SPD biharmonic and elasticity systems in [warp-preconditioners](https://github.com/alecjacobson/warp-preconditioners). These workloads need a stronger preconditioner built and applied in Warp, including repeated solves with fixed sparsity and changing numerical entries.

**This is a handoff PR on `alecjacobson/warp`. Alec will repost it to internal NVIDIA Warp from another machine.**

## What does this change?

Add `warp.optim.linear.FSAI` and `preconditioner(A, "fsai")`. Adaptive, diagonally equilibrated row construction produces a lower-triangular factor `G`; application uses `G.T @ G`. Square BSR blocks are scalarized on device. No multigrid, external factorization, SciPy numerical backend, benchmarks, assets, or experimental block preconditioners are included.

Retain batched support growth, optional float32 factor storage with matrix-precision accumulation, cooperative CUDA application, and transactional fixed-pattern refits. The eight-file diff includes the implementation, tests, and API/documentation/test registration.

Support native `float16`, `float32` and `float64` construction, factors, refits and application. Half precision specializes the existing kernels with a `1e-3` pivot floor; it does not promote the matrix or vectors to float32. Float32/float64 numerical helpers are unchanged. Two dtype-specific zero constants also fix CR compilation for half-precision inputs.

```python
from warp.optim.linear import FSAI, cg

M = FSAI(A, max_row_size=16, reuse_pattern=True)
cg(A, b, x, M=M)
# Modify A.values while preserving compact BSR topology.
M.update()
cg(A, b, x, M=M)
```

The review fixed two bugs in the downstream implementation: `kap_tolerance=0` could still stop growth when improvement rounded to zero, and reusable empty matrices failed on a zero-length slice. Construction now also checks factor validity before publication without adding a validation kernel or synchronization.

Input must be canonical SPD BSR with both triangles stored; global symmetry/SPD validation is not performed. Setup/refits synchronize. Warmed application supports CUDA graph capture. Each instance owns scratch and must not be applied concurrently on separate streams. Refits preserve supports and reject invalid updates without changing either factor. No automatic differentiation is provided.

## Validation

- **43 FSAI tests passed**, CPU and CUDA. Independent NumPy oracles check full-pattern inverses, local solves, adaptive supports and true CG/CR residuals. Other coverage includes float16/float32/float64, mixed storage, scalar/1x1/3x3 blocks, padded input, unused capacity, all lane counts and alias patterns, failed-update rollback, and graph replay after updates.
- **82 Warp linear-solver tests passed**, CPU and CUDA. The shared dtype/scaled-block checks now include FSAI. Half-precision CG/CR tests check true residuals with scalar Jacobi, direct/sequential block Jacobi and FSAI, using scalar and vector-valued RHS arrays.
- **208 downstream repository tests passed** after backporting the changes.
- Regression validation: the original 32-row tridiagonal reproducer stopped at 20 entries despite zero tolerance; the corrected implementation reaches 32. Reusable empty matrices originally raised on `columns[:0]`; construction/application/update now succeed on CPU and CUDA.
- Float32/float64 regression: nine alternating-order paired trials in 10 CPU/CUDA configurations, covering biharmonic grids and SimJEB fTetWild elasticity. Construction kernel hashes match; factors, applications and 100-step CG solutions are bitwise identical to `8b0e91e`. No meaningful slowdown in setup/refit/application/CG timings: the largest median increase was 2.02%. Compilation, assembly and cyclic garbage collection were excluded; GPU-overlapping configurations were discarded and repeated. [Methodology and results](https://github.com/alecjacobson/warp-preconditioners/blob/main/results/fsai-float16-regression.txt), [raw samples](https://github.com/alecjacobson/warp-preconditioners/blob/main/results/fsai-float16-regression.json). Benchmark code and assets stay outside this PR.

- API documentation builds without warnings. All applicable pre-commit checks pass.
