Title: [BUG] FEM magnetostatics: incompatible discrete load prevents convergence

### Bug Description

The default FEM magnetostatics example does not reach its requested residual tolerance. Its assembled current load has a substantial component along the curl–curl operator's gradient nullspace, including when the geometry and system are freshly assembled in float64.

The prescribed physical current appears compatible: it circulates around the coil, is divergence-free, and is tangent to the surfaces where its support ends. The issue is with compatibility of the **discrete assembled load**, rather than the physical loading itself.

The [example already notes that the RHS may not lie in the matrix image](https://github.com/NVIDIA/warp/blob/5a0c33d17d847d0be07ae1003263b572aae0729a/warp/examples/fem/example_magnetostatics.py#L243). The measurements below suggest this is large enough to prevent a meaningful solve to the stated tolerance, not just a small float32 effect.

#### Reproduction

The original example runs with:

```sh
python -m warp.examples.fem.example_magnetostatics --device cuda:0 --headless --fp64
```

For an independent true-residual and nullspace check, download this [standalone diagnostic](https://github.com/alecjacobson/warp-preconditioners/blob/82c9a1e/benchmarks/warp_magnetostatics_diagnostic.py) and run it with the same Warp installation:

```sh
python warp_magnetostatics_diagnostic.py --fp64
python warp_magnetostatics_diagnostic.py
```

It captures the original example's boundary-projected matrix and RHS, uses stock Jacobi + CR, and increases the iteration limit from 250 to 2,000. Assembly, interpolation, and solves run in Warp on CUDA. NumPy is used only for diagnostic reductions and generation of the seeded control vector; there is no external sparse solver.

#### Results

Default grid resolution 32, radius 2, current 1e6: 104,544 unknowns.

For fresh float64 assembly, construct a discrete gradient `q` from a scalar Q1 field with zero boundary values. The scalar probe comes from the assembled current/gradient pairing. Its gradient is constructed on the undeformed base grid, retaining reference edge DOFs under the covariant Piola map.

```text
||b||                              92438.74661
||K||_F                            2.130662219e9
||q||                              2.070196678
||K^T q||                          2.191144105e-9
||K^T q|| / (||K||_F ||q||)         4.967578382e-19
|q^T b| / (||q|| ||b||)             0.216024690
```

A gradient mode annihilated by the matrix transpose to roundoff thus captures **21.6% of the load**, while the requested relative residual is **0.01%**. Float32 assembly gives essentially the same compatibility defect.

| Load, freshly assembled float64 matrix | Jacobi + CR iterations | True relative residual |
| --- | ---: | ---: |
| Original current load | 2,000 (limit) | 0.362870335 |
| Manufactured compatible load `K*x*` | 30 | 8.95099e-5 |

Both use the same matrix, zero initial guess, and tolerance `1e-4`. The seeded control `x*` is zero on the boundary. The control has a different, potentially easier RHS; this is a compatibility/control check, not a performance comparison. [Full float64 results](https://github.com/alecjacobson/warp-preconditioners/blob/82c9a1e/results/magnetostatics-diagnostic/float64.json).

#### Interpretation / expected behavior

This is **not necessarily an issue with the choice of iterative solver**. For the intended singular operator, an incompatible load component cannot be removed by changing solvers or preconditioners, or simply allowing more iterations. Rounding can lift null modes, so the diagnostic is not a claim of exact algebraic inconsistency of the stored floating-point matrix.

Ideally the example should assemble a discretely compatible load and converge to its stated tolerance. If an approximate least-squares solution is intentional, it should document that objective and use a corresponding convergence criterion, while reporting the true residual.

The precise assembly mechanism has not yet been isolated; quadrature across the sharp coil boundaries is one possibility. Gradient gauge freedom is expected and is not itself a bug. These measurements also do not establish that the rendered magnetic field `curl(A)` is inaccurate.
